# NPB球団経営シミュレーション 設計計画

## 1. 調査結果の要点

### 1-1 打席結果の計算（オッズ比法 / log5）
- 結果カテゴリごとに「打者の率 B」「投手の率 P」「リーグ平均 L」を持ち、
  `odds = (B/(1-B)) * (P/(1-P)) / (L/(1-L))`、`p = odds/(1+odds)` で対戦確率を作る（Tango/Haechrel の一般化 log5）。
- 多項目版：K → BB → HBP → 打球(BIP) の順に条件付きで決め、BIP は 打球種別（ゴロ/フライ/ライナー/内野フライ）→ 安打化率 → 長打種別 と段階的に決める（各段階で log5）。こうすると合計が必ず 1 になり、各能力が独立に効く。
- 補正は全て「オッズに倍率を掛ける」形で入れる：左右相性（打者の L/R スプリット係数）、球場（HR・2B・3B・安打のパークファクター）、守備（BIP安打率に守備者の能力を反映）、投手疲労（球数/スタミナで球威・制球を低下）、調子。

### 1-2 走者・守備・疲労・左右
- 進塁：打球種別×打球方向×アウトカウント×塁状況の基本確率表（MLB/NPBのRetrosheet系研究の一般値：単打で二塁走者生還 約60%、一塁→三塁 約28% 等）＋走力・外野手の肩で補正。
- 併殺：一塁走者あり・2アウト未満のゴロで 打者走力・内野守備から計算（NPBのGIDP率 ≒ 機会の11%前後）。
- 失策：守備者の捕球能力から打球ごとに判定。
- 疲労：投球数を1球ずつシミュレートせず、打席ごとに結果別の期待球数（K≈4.8, BB≈5.7, BIP≈3.3 等）で加算。スタミナ閾値を越えると能力が段階的に低下。連投・登板間隔で回復量を管理。
- 左右：同側不利の一般値（打者がplatoon不利で wOBA −約.025〜.030）を基準に、選手個別の係数を持たせる。

### 1-5 セイバーメトリクス
- wOBA = (wBB·uBB + wHBP·HBP + w1B·1B + w2B·2B + w3B·3B + wHR·HR) / (AB + BB − IBB + SF + HBP)
  - 係数は**ゲーム内リーグ実績から毎年計算**：得点期待値表（RE24）→ 各イベントの得点価値 → アウト価値を足してスケーリングし、リーグwOBA=リーグOBPに合わせる。
- wRAA = (wOBA − lgwOBA)/wOBAscale × PA、wRC+ = ((wRAA/PA + lgR/PA) + (lgR/PA − PF·lgR/PA)) / (lgwRC/PA) × 100
- OPS+ = 100 × (OBP/lgOBP + SLG/lgSLG − 1) / PF、ISO = SLG − AVG、BABIP = (H−HR)/(AB−K−HR+SF)
- FIP = (13·HR + 3·(BB+HBP) − 2·K)/IP + C（C = lgERA − リーグの同式）
- ERA+ = 100 × lgERA / ERA × PF
- WAR：野手 = (打撃wRAA + 走塁 + 守備 + ポジション補正 + リーグ補正 + 代替水準) / 1勝あたり得点（RPW = 9×(lgR/IP)×1.5+3 で毎年計算）。投手 = FIPベース。
- パークファクター：(本拠地での得点+失点)/(ビジター)を3年平均・回帰付きで算出。

## 2. 全体アーキテクチャ
```
src/
  engine/      純粋TS。DOM非依存。乱数はシード付き（再現可能）
    rng.ts  types.ts  ratings.ts  pa.ts(打席) baserunning.ts  game.ts  manager-ai.ts  fatigue.ts
  league/      日程生成・順位・ポストシーズン・ルール設定
  stats/       集計・セイバー指標・リーグ定数計算
  players/     生成・成長・衰え・ケガ・引退・スカウト評価
  amateur/     高校・大学・大会進行
  front/       ドラフト・FA・トレードAI・契約・財政
  news/        新聞の見出し生成・重要度スコア
  worker/      Web Worker（シーズン一括計算）
  save/        IndexedDB（複数枠、JSON書き出し/読込）
  ui/          画面（フレームワークは軽量に：Preact or 素のTS＋小さな仕組み）
tests/         Vitest
```
- 状態は1つの `World` オブジェクト（正規化された選手・球団・学校・成績・記事）。Worker に渡して日単位で進め、差分を返す。
- 乱数はシード付き（mulberry32等）で、テストを決定的にする。

## 5. フェーズ1 結果（試合エンジン）
- `src/engine/` に純粋TSのエンジン（DOM非依存・シード付き乱数で再現可能）
  - `pa.ts` 打席（オッズ比法、左右・守備・球場・疲労・調子・打順巡目）
  - `game.ts` 試合進行（走塁表＋走力/肩補正、併殺、犠飛、進塁打、失策、盗塁、バント、スクイズ、エンドラン、敬遠、暴投、サヨナラ、12回引分、勝敗・S・H）
  - `ai.ts` 采配AI（継投の役割、連投制限、代打・代走・守備固め、作戦）
  - `step()` で1打席ずつ進められる（観戦用）、`log:false` で高速一括計算（約0.7ms/試合）
- 1シーズン（12球団×143試合、DHあり）3シード平均:
  打率.245 / 得点3.25 / 本塁打0.65 / 防御率3.10 / K% 19.5 / BB% 7.5 / BABIP .294 / 盗塁0.39 / 犠打0.38 / 併殺0.63 / 失策0.45（いずれも1チーム1試合あたり）
- DHなしでは 打率.239 / 得点3.05 / 犠打0.54 と、セ・リーグらしく下がる

- リーグ基準補正: 能力の平均が年々ずれても打撃環境がNPB水準に保たれるよう、エンジンはリーグ平均との差で計算
- 14シーズンの自動進行で、一軍の平均総合値・平均年齢・年俸総額・リーグ打率/防御率が安定することを確認
